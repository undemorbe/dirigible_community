# Сайт АНО «Дирижабль»

Статический сайт Центра развития социальных практик «Дирижабль» (dirigible.community).
Дизайн-система — **«Вязаное полотно»**: лицевая гладь, жемчужная вязка, косички и заплатки
в тёплой шерстяной палитре, поверх фирменных синего и оранжевого из логотипа-дирижабля.

## Быстрый старт

```bash
python3 tools/build.py && python3 -m http.server 8123
```

Затем открыть http://localhost:8123. Зависимостей ставить не нужно — только Python 3.

## Команды

| Команда | Что делает |
|---|---|
| `python3 tools/build.py` | Собирает все HTML-страницы, редиректы, `sitemap.xml` и `robots.txt` |
| `python3 tools/check.py` | Проверяет сборку: битые ссылки и якоря, дубли `id`, заголовки, `alt`, внешние ссылки |
| `python3 tools/make_yarn.py` | Пересобирает SVG-тайлы пряжи для мотива «Амигуруми» |
| `python3 -m http.server 8123` | Локальный сервер для просмотра |

Сборка с боевыми счётчиками и платёжной формой (значения — см. `.env.example`):

```bash
set -a && . ./.env && set +a && python3 tools/build.py
```

## Структура

```
tools/build.py            генератор страниц: данные, шаблоны, весь контент
tools/check.py            валидатор собранного сайта
assets/css/knit.css          основная дизайн-система
assets/css/amigurumi.css     мотив «Амигуруми» (только knit-demo.html)
assets/css/donate-widget.css тема платёжной формы (грузится в shadow DOM виджета)
assets/js/app.js          меню, карусели, анимации появления
assets/js/articles.js     лента материалов
assets/js/analytics.js    заглушка аналитики для разработки
assets/data/articles.json данные ленты
assets/img/               SVG-текстуры вязки и media/ с фотографиями
legacy/                   исходная выгрузка Craftum CMS (архив)
*.html                    результат сборки — не редактировать вручную
```

## Как править

Контент и разметка страниц живут в `tools/build.py`, стили — в `assets/css/knit.css`,
материалы ленты — в `assets/data/articles.json`. После правки нужно пересобрать сайт.

HTML-файлы в корне перезаписываются сборкой, править их напрямую бессмысленно.

## Что изменилось относительно старой версии

- Сайт пересобран с нуля: вместо выгрузки Craftum с ID-селекторами и абсолютным позиционированием —
  семантическая вёрстка и адаптивная сетка, mobile-first.
- Шапка и подвал больше не дублируются в 11 файлах: навигация правится одной строкой в `NAV`.
- Лента материалов работает: раньше она стучалась в закрытый эндпоинт Craftum и всегда была пустой,
  а в разметке висели демо-статьи конструктора.
- Изображения скачаны локально — сайт больше не зависит от чужого CDN.
- Боевые счётчики аналитики удалены, чтобы локальная разработка не слала хиты в продовую статистику.
- Старые адреса (`page2.html` и т. д.) сохранены как редиректы на новые страницы.

## Переменные окружения и секреты

Идентификаторы счётчиков и платёжного виджета **не хранятся в репозитории**. Сборка берёт их
из переменных окружения; пустые значения не ломают сборку — счётчики просто не подключаются,
а у формы пожертвования показывается запасной блок с реквизитами.

| Переменная | Что это | Где взять |
|---|---|---|
| `YANDEX_METRIKA_ID` | Номер счётчика Яндекс.Метрики | Метрика → Настройки → Номер счётчика |
| `TOP_MAIL_RU_ID` | Номер счётчика Top.Mail.Ru | top.mail.ru → счётчик → ID |
| `DONATION_WIDGET_ID` | UUID загрузчика виджета donation.ru | Из ссылки `wloader/<UUID>/wloader.js` |
| `DONATION_FORM_ID` | UUID общей платёжной формы | Атрибут `id` у `<mixplat-form>` |
| `DONATION_FORM_ID_VANYA` | UUID формы сбора для Вани (необязательно) | Кабинет donation.ru |
| `DONATION_FORM_ID_BROTHERS` | UUID формы сбора для Максима и Коли (необязательно) | Кабинет donation.ru |
| `SITE_URL` | Адрес сайта для canonical, og:url и sitemap | — |

Строго говоря, это не секреты: счётчики и виджет видны в HTML любому посетителю. Выносим их
из репозитория по другой причине — чтобы форк, локальная сборка или чужой стенд не слали хиты
в боевую статистику организации и не показывали её платёжную форму.

### Куда вписать на GitHub

`Settings` → `Secrets and variables` → `Actions` → вкладка **Secrets** → `New repository secret`.
Создать четыре секрета с именами ровно как в таблице выше:

```
YANDEX_METRIKA_ID
TOP_MAIL_RU_ID
DONATION_WIDGET_ID
DONATION_FORM_ID
```

`SITE_URL` — на вкладке **Variables** (не Secrets), и только если нужен адрес, отличный от
`https://<владелец>.github.io/<репозиторий>`: например, когда сайт стоит на своём домене.
Без него workflow подставит адрес GitHub Pages автоматически.

Локально те же переменные кладутся в `.env` — файл в `.gitignore`, шаблон в `.env.example`.

### Адресность сборов

Сейчас страницы `help-vanya.html` и `help-brothers.html` используют **ту же** платёжную форму,
что и общая страница «Помочь»: пожертвование уходит в общий проект организации без привязки
к конкретному адресату. Так было и в исходной версии сайта.

Чтобы сборы стали действительно адресными, есть два пути:

1. Завести в кабинете donation.ru отдельные формы под каждый сбор и указать их id
   в `DONATION_FORM_ID_VANYA` и `DONATION_FORM_ID_BROTHERS` — код уже это поддерживает,
   правок не потребуется.
2. Включить в форме поле «Назначение» (`targets`) и завести адресатов — тогда жертвователь
   выберет получателя сам. Сейчас это поле в настройках формы выключено.

## Деплой

`.github/workflows/deploy.yml` при пуше в `main` собирает сайт, прогоняет `tools/check.py`
и публикует результат на GitHub Pages. Pull request'ы только собираются и проверяются,
без публикации.

Перед первым запуском нужно один раз включить Pages:
`Settings` → `Pages` → `Build and deployment` → `Source: GitHub Actions`.

Из артефакта исключаются `legacy/`, `tools/` и `*.md` — на проде они не нужны.

## Демонстрация мотива

`knit-demo.html` — отдельная страница с более объёмным вариантом вязаного стиля: полотна
из толстой пряжи, обвязка крючком, кнопки-пуговицы, вязаная анкета с вышитыми галочками.
В меню сайта не выводится, открывается по прямой ссылке.
