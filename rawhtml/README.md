# rawhtml/ — страница для блока «HTML-код» в Craftum

Эксперимент: можно ли перенести сайт в Craftum не по блокам конструктора,
а одним куском HTML.

`index.html` — главная страница целиком: разметка, стили и скрипт в одном
файле. Страница **не свёрстана заново** — она собрана из самой сборки сайта,
поэтому выглядит один в один с `index.html` в корне репозитория.

## Что умеет Craftum

Проверено по их [базе знаний](https://craftum.com/help/). Свой код
вставляется на нескольких уровнях:

| Куда | Где в интерфейсе | Для чего |
|---|---|---|
| **Блок «HTML-код»** | «+» под блоком → вкладка «Другое» → «HTML-код» → «Настроить» | произвольная разметка в конкретном месте страницы |
| **Элемент «Код»** | внутри дизайн-блока | то же, но внутри уже свёрстанного блока |
| **Настройки страницы → HTML** | код перед закрывающим `</head>` | подключение библиотек для одной страницы |
| **Настройки сайта → HTML → «Пользовательский HTML»** | шестерёнка → вкладка «HTML» | счётчики, чаты, виджеты на всех страницах |

Дополнительно блокам и элементам конструктора можно задавать свой
CSS-класс (настройки блока → «Контент» → CSS → Class Name) и красить
их стилями из блока «HTML-код» — так Craftum сам советует делать
градиентные заголовки.

Внутри блока работают и `<style>`, и `<script>`: код выполняется
на публикации, а не только в превью.

## Как вставить

1. Открыть страницу в редакторе Craftum.
2. «+» → «Другое» → «HTML-код» → «Настроить».
3. Скопировать **всё содержимое `index.html`** в поле.
4. Опубликовать страницу и открыть сайт.

## Как собирается

```bash
python3 tools/build.py        # сначала обычная сборка сайта
python3 tools/make_rawhtml.py # затем блок
```

Генератор берёт готовое и ничего не верстает сам:

- разметка — секция `<main>` из собранного `index.html`;
- стили — весь `assets/css/knit.css`;
- поведение — весь `assets/js/app.js`.

Правки дизайна идут в `build.py` / `knit.css` / `app.js` как обычно и
попадают в блок при пересборке. **`rawhtml/index.html` руками не править** —
перезапишется.

## Что генератор меняет при переносе

- **Скоупит весь CSS под `.dzb`.** `:root`, `html` и `body` становятся
  самим блоком, остальные селекторы получают префикс. Специфичность
  сдвигается одинаково у всех правил, поэтому расстановка приоритетов
  внутри `knit.css` не меняется — именно это и даёт совпадение с сайтом
  один в один.
- **Делает пути абсолютными.** Внутри блока нет ни `assets/`, ни соседних
  страниц, поэтому картинки, текстуры и ссылки ведут на нашу сборку
  (константа `BASE` в `tools/make_rawhtml.py`). Если сайт переедет на
  другой адрес — поменять там и пересобрать.
- **Добавляет два защитных слоя.** Больше ничего своего в стилях нет:
  - сброс чужих правил (`p`, `h2`, `img`, `button` на странице
    конструктора бьют наследование от `.dzb`), завёрнутый в `:where()` —
    нулевая специфичность, чтобы слой не победил сам `knit.css`;
  - фиксация цвета кнопок с `!important`: тема конструктора красит
    ссылки своим акцентом, и белая надпись на оранжевой кнопке
    однажды уже слилась с фоном.
- **Оборачивает запуск `app.js`** флагом `data-dzb-ready` — блок могут
  вставить на страницу дважды.

Фрагмент намеренно без `<!doctype>`, `<html>`, `<head>` и `<body>`:
Craftum вставляет его внутрь своей страницы.

## Локальная проверка

`preview.html` — обвязка, имитирующая чужую страницу Craftum: вокруг блока
намеренно уродливые красные стили на `p`, `h2`, `img`, `button` и
перекраска всех ссылок через `!important`. Если блок выглядит как сайт,
а обвязка осталась красной — изоляция работает в обе стороны.

```bash
python3 -m http.server 8123
# http://localhost:8123/rawhtml/preview.html   — блок
# http://localhost:8123/index.html             — оригинал для сравнения
```

Через `file://` не откроется: обвязка подтягивает `index.html` через `fetch`.
В Craftum сама `preview.html` не нужна.

## Ограничения

- Переносится только `<main>`: шапка и подвал остаются за конструктором.
  Их тоже можно отдать своим HTML — отдельными блоками, но тогда надо
  гасить штатные шапку и подвал Craftum.
- Формы пожертвований и оплаты в блок не попадают: на главной их нет,
  а на `donate.html` им нужен внешний загрузчик и точка монтирования
  `<mixplat-form>` — это отдельная задача.
- Шрифты тянутся с Google Fonts; при недоступности подставляется
  системный фолбэк из `font-family`.
