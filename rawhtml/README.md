# rawhtml/ — страница для блока «HTML-код» в Craftum

Эксперимент: можно ли перенести дизайн «Вязаное полотно» в Craftum
не по блокам конструктора, а одним куском HTML.

`index.html` — одна тестовая страница (главная) целиком: разметка,
стили и скрипты в одном файле, внешних ассетов нет.

## Что умеет Craftum

Проверено по их [базе знаний](https://craftum.com/help/). Свой код
вставляется на трёх уровнях:

| Куда | Где в интерфейсе | Для чего |
|---|---|---|
| **Блок «HTML-код»** | «+» под блоком → вкладка «Другое» → «HTML-код» → «Настроить» | произвольная разметка в конкретном месте страницы |
| **Элемент «Код»** | внутри дизайн-блока | то же, но внутри уже свёрстанного блока |
| **Настройки страницы → HTML** | код перед закрывающим `</head>` | подключение библиотек для одной страницы |
| **Настройки сайта → HTML → «Пользовательский HTML»** | шестерёнка → вкладка «HTML» | счётчики, чаты, виджеты на всех страницах |

Дополнительно блокам и элементам конструктора можно задавать свой
CSS-класс (настройки блока → «Контент» → CSS → Class Name) и красить
их стилями из блока «HTML-код» — так Craftum сам советует делать
градиентные заголовки.

Внутри блока работают и `<style>`, и `<script>`: код выполняется
на публикации, а не только в превью.

## Как вставить

1. Открыть страницу в редакторе Craftum.
2. «+» → «Другое» → «HTML-код» → «Настроить».
3. Скопировать **всё содержимое `index.html`** в поле.
4. Опубликовать страницу и открыть сайт.

На опубликованной странице внизу блока есть панель «Проверка блока» —
её заполняет собственный скрипт блока. Семь галочек означают, что
конструктор ничего не вырезал: дошли и стили, и скрипт, и шрифты,
и встроенные текстуры.

## Почему файл устроен именно так

- **Нет `<!doctype>`, `<html>`, `<head>`, `<body>`.** Craftum вставляет
  фрагмент внутрь своей страницы; эти теги там не нужны и будут отброшены.
- **Всё под селектором `.dzb`, классы и переменные с префиксом `dzb-`.**
  Стили конструктора остаются нетронутыми, наши наружу не текут.
- **Локальный сброс завёрнут в `:where()`.** На странице конструктора
  висят свои правила на `p`, `h2`, `img`, `button`, и они бьют
  наследование от `.dzb`. Сбрасывать приходится явно, но `:where()`
  даёт нулевую специфичность — иначе `.dzb p` побеждал бы `.dzb-lead`
  и собственные стили компонентов не применялись бы.
- **SVG-тайлы вязки встроены как `data:` URI.** В блоке нет своей
  файловой структуры, ссылаться на `assets/img/` неоткуда.
- **Фотографии — с CDN организации** (`274418.selcdn.ru`), это те же
  оригиналы, что уже лежат в медиатеке Craftum.
- **Клубки нарисованы инлайновым SVG.** В SVG, подключённом через
  `url()` или `<img>`, `currentColor` не наследуется, и покрасить
  их из CSS было бы нельзя.
- **Скрипт в IIFE и с флагом `data-dzb-ready`.** Блок можно вставить
  дважды — глобальных имён не остаётся, повторная инициализация
  не происходит.

## Правки

Исходник — `tools/rawhtml.tpl`, сборка:

```bash
python3 tools/make_rawhtml.py
```

Скрипт минифицирует SVG-тайлы в `data:` URI и подставляет список команды.
Редактировать `rawhtml/index.html` руками не надо — перезапишется.

## Локальная проверка

`preview.html` — обвязка, имитирующая чужую страницу Craftum: вокруг
блока намеренно уродливые красные стили на `p`, `h2`, `img`, `button`.
Если блок выглядит правильно, а обвязка осталась красной — изоляция
работает в обе стороны.

```bash
python3 -m http.server 8123
# http://localhost:8123/rawhtml/preview.html
```

Через `file://` не откроется: обвязка подтягивает `index.html` через `fetch`.
В Craftum сама `preview.html` не нужна.

## Ограничения

- Блок статичен: формы пожертвований и оплаты сюда не включены —
  им нужны внешние загрузчики и точки монтирования, это отдельная задача.
- Шапка и подвал не дублируются: их даёт сама страница Craftum.
- Шрифты тянутся с Google Fonts через `@import`; при недоступности
  подставляется системный фолбэк из `font-family`.
