# rawhtml/ — перенос сайта в Craftum своим HTML

Craftum даёт вставлять свой код на двух уровнях, и это ровно то, как устроен
обычный сайт: общая обвязка отдельно, содержимое страниц отдельно.

```
rawhtml/site-html.html    → «Настройки сайта» → «HTML» → «Пользовательский HTML»
rawhtml/pages/<имя>.html  → блок «HTML-код» на соответствующей странице
```

Страницы **не свёрстаны заново** — они собраны из самой сборки сайта,
поэтому выглядят один в один с `index.html`, `about.html` и остальными
в корне репозитория.

## Что умеет Craftum

Проверено по их [базе знаний](https://craftum.com/help/).

| Куда | Где в интерфейсе | Для чего |
|---|---|---|
| **Настройки сайта → HTML → «Пользовательский HTML»** | шестерёнка → вкладка «HTML» | сквозной код на все страницы: стили, скрипты, счётчики, чаты |
| **Настройки страницы → HTML** | настройки страницы → «HTML» | код перед `</head>` для одной страницы |
| **Блок «HTML-код»** | «+» под блоком → «Другое» → «HTML-код» → «Настроить» | произвольная разметка в конкретном месте страницы |
| **Элемент «Код»** | внутри дизайн-блока | то же, но внутри уже свёрстанного блока |

Чистый CSS и JS в поле «Пользовательский HTML» надо оборачивать в `<style>`
и `<script>` — что и сделано. Блокам конструктора можно задавать свой
CSS-класс (настройки блока → «Контент» → CSS → Class Name) и красить их
нашими стилями.

## Порядок действий

1. **Один раз на сайт.** «Настройки сайта» → вкладка «HTML» → вставить всё
   содержимое `site-html.html` в поле «Пользовательский HTML» → «Сохранить»
   → **«Опубликовать все страницы»**.
2. **На каждую страницу.** Открыть страницу → «+» → «Другое» → «HTML-код» →
   «Настроить» → вставить содержимое соответствующего файла из `pages/` →
   опубликовать.

Без шага 1 блоки будут без оформления: стили и скрипты лежат только в
сквозном коде.

## Что внутри

**`site-html.html`** (~60 КБ) — шрифты Comfortaa и Nunito, весь
`assets/css/knit.css`, весь `assets/js/app.js` и `assets/js/articles.js`.
Аналитики здесь нет: счётчики в Craftum ставятся его собственными средствами,
в том же поле.

**`pages/`** — 12 файлов, по одному на страницу: `index`, `about`, `news`,
`research`, `donate`, `reports`, `documents`, `education`, `program`,
`effective`, `survey-clients`, `survey-specialists`. Только разметка.

Не переносятся: `knit-demo.html` (у него свой `amigurumi.css`), `404.html`
(конструктор отдаёт свою) и редирект-заглушки старых адресов Craftum —
в конструкторе у страниц свои URL.

## Как собирается

```bash
python3 tools/build.py        # сначала обычная сборка сайта
python3 tools/make_rawhtml.py # затем сквозной код и блоки
```

Генератор берёт готовое: разметку — из секций `<main>` собранных страниц,
стили — из `knit.css`, поведение — из `app.js` и `articles.js`. Правки
дизайна идут в исходники как обычно и попадают сюда при пересборке.
**Файлы в `rawhtml/` руками не править** — перезапишутся.

## Что генератор меняет при переносе

- **Скоупит весь CSS под `.dzb`.** `:root`, `html` и `body` становятся самим
  блоком, остальные селекторы получают префикс. Специфичность сдвигается
  одинаково у всех правил, поэтому расстановка приоритетов внутри `knit.css`
  не меняется — именно это и даёт совпадение с сайтом один в один.
- **Делает пути абсолютными** — внутри блока нет ни `assets/`, ни соседних
  страниц. Кроме `src`/`href` это касается `data-donate-style` (тема виджета
  пожертвований) и `data-articles-endpoint` (адрес ленты). Ленте дополнительно
  проставляется `data-articles-base`: пути внутри `articles.json` относительные,
  и разрешать их на чужом домене не от чего.
- **Добавляет два защитных слоя.** Больше ничего своего в стилях нет:
  - сброс чужих правил (`p`, `h2`, `img`, `button` на странице конструктора
    бьют наследование от `.dzb`), завёрнутый в `:where()` — нулевая
    специфичность, чтобы слой не победил сам `knit.css`;
  - фиксация цвета кнопок с `!important`: тема конструктора красит ссылки
    своим акцентом, и белая надпись на оранжевой кнопке однажды уже слилась
    с фоном.
- **Защищает от повторного запуска.** Сквозной код держит флаг
  `window.__dirigibleBooted`, блоки — `data-dzb-ready`, лента —
  `data-articles-ready`. Блоки, которые конструктор дорисовал позже,
  доинициализируются через `MutationObserver`.

Фрагменты намеренно без `<!doctype>`, `<html>`, `<head>` и `<body>`:
Craftum вставляет их внутрь своей страницы.

## Где лежат картинки

Craftum раздаёт только то, что загружено в его медиатеку, поэтому ассеты
тянутся с нашей сборки на GitHub Pages — константа `BASE` в
`tools/make_rawhtml.py`. Сайт переедет (например на Cloudflare Pages) —
поменять её и пересобрать.

## Локальная проверка

`preview.html` — обвязка, имитирующая страницу конструктора: сквозной код
подключается как «Пользовательский HTML», блок — как блок «HTML-код».
Вокруг намеренно уродливые красные стили на `p`, `h2`, `img`, `button` и
перекраска всех ссылок через `!important`. Если блок выглядит как сайт,
а обвязка осталась красной — изоляция работает в обе стороны.
Страница выбирается списком наверху.

```bash
python3 -m http.server 8123
# http://localhost:8123/rawhtml/preview.html   — блок
# http://localhost:8123/news.html              — оригинал для сравнения
```

Через `file://` не откроется: обвязка подтягивает файлы через `fetch`.
В Craftum сама `preview.html` не нужна.

## Ограничения

- Переносится только `<main>`: шапка и подвал остаются за конструктором.
  Их тоже можно отдать своим HTML, но тогда надо гасить штатные.
- Виджет пожертвований и форма оплаты курса подтягиваются внешними
  загрузчиками, которых в сквозном коде нет: их идентификаторы живут
  в переменных окружения сборки. На `donate.html` без загрузчика
  показывается запасной блок с реквизитами — это штатное поведение.
